Windows 11, Python 3.12.

seed (39 ms per filter step) without it, about the same for 4 and 6 drones (numpy call overhead,

The rows under a function overlap (nested calls). The backup rollout flies 66 to 109 steps of small
(M, 3) numpy operations for every pair on every filter step, so per-call overhead dominates.

Implications for PR 2: the rollout is the only large target (Numba or a scalar loop). OSQP warm start
can save at most the 0.5 % in `osqp.solve`; reworking the sparse build at most about 8 %.
